# Scan app implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a macOS app and CLI that scan multi-page documents from the HP M130a over USB into one
PDF, per [the design](../specs/2026-11-11-scan-app-design.md).

**Architecture:** a Rust workspace in `app/`. `scan-core` holds every printer-facing piece behind a
`Transport` trait (USB in production, a scripted fake in tests). `scan-cli` and a Tauri 2 app are
thin layers over it. The UI is TypeScript without a framework, using Tauri's global API object so
it has no npm runtime dependencies.

**Tech stack:** Rust 1.99 (nixpkgs), nusb 0.2, httparse 1.10, quick-xml 0.42, pdf-writer 0.15,
thiserror 2, clap 4, anyhow 1, tauri 2.12 + tauri-plugin-dialog 2.8, lopdf (tests); Bun 1.4,
Biome 2.6, Vitest; cargo-tauri 2.12. Check docs.rs for the exact current API of each crate before
using it; versions above were current on 2026-11-11.

**Unlike the firmware plan, tasks here specify interfaces, behaviour and tests rather than full
code.** Implementers write the code test-first. Interfaces named below are contracts between
tasks: keep their names and signatures, or report why they must change.

**Standards (apply to every task):**
- Zero warnings: `cargo clippy --all-targets -- -D warnings` with the workspace lints below,
  `cargo fmt --check`, Biome clean.
- Functions ≤ 100 lines, cyclomatic complexity ≤ 8, ≤ 5 parameters, lines ≤ 100 characters
  (`just app-lint` checks all four, Rust and TypeScript).
- No `unwrap`/`expect`/`panic` outside tests. Errors carry context and say what to do.
- Tests verify behaviour, cover edges and error paths, mock only the USB boundary.
- Comments only for *why*. Fail fast.
- Commits: one logical change each, imperative mood, ≤ 72-character subject. Commits are signed
  through the user's 1Password SSH agent; never bypass signing. Never push.

## Task 2: Transport trait and HTTP framing

**Files:** `scan-core/src/{transport.rs,http.rs,testing.rs}`, tests inline (`#[cfg(test)]`) or in
`scan-core/tests/`.

```rust
pub trait Transport {
    /// Writes one whole request (the implementation adds a zero-length packet when needed).
    fn write(&mut self, data: &[u8]) -> Result<(), TransportError>;
    /// Returns the next non-empty bytes, waiting until `deadline` at most.
    fn read(&mut self, deadline: Instant) -> Result<Vec<u8>, TransportError>;
    /// Discards bytes left from an earlier exchange, up to the first empty read; returns the count.
    fn drain(&mut self) -> Result<usize, TransportError>;
}
#[derive(Debug, thiserror::Error)]
pub enum TransportError { Timeout, Disconnected, Io(String) }
```

- `testing.rs` (behind `#[cfg(any(test, feature = "testing"))]`, feature `testing` exported for
  other crates' tests): `ScriptedTransport` — constructed from a list of expected exchanges
  `(request_line_prefix, response_bytes, split: Vec<usize>)`. `write` checks the request starts
  with the expected method + path (fail with a clear message otherwise) and queues the response;
  `read` returns it in the given split sizes; `Timeout` when nothing is queued. Records all writes
  for assertions. Helper to load fixture files from `tests/fixtures/`.
- `http.rs`:
  ```rust
  pub struct Request<'a> { pub method: &'a str, pub path: &'a str,
                           pub content_type: Option<&'a str>, pub body: &'a [u8] }
  pub fn encode_request(request: &Request) -> Vec<u8>;
  pub struct Response { pub status: u16, pub headers: Vec<(String, String)>, pub body: Vec<u8> }
  impl Response { pub fn header(&self, name: &str) -> Option<&str>; } // case-insensitive
  pub fn exchange<T: Transport>(t: &mut T, request: &Request, timeout: Duration)
      -> Result<Response, HttpError>; // drain, write, read one response by `now + timeout`
  ```
- Encoding matches `probe/httpipp.py`'s `build_request`: request line, `Host: localhost`,
  `Connection: keep-alive`, `Content-Type` + `Content-Length` when there is a body or the method
  is POST. Golden test: encoding the captured ScanJobs POST
  (`tests/fixtures/m130a-scanjobs-request.http`) from its parts reproduces it byte for byte.
- Response framing, same rules as `firmware/src/http_framer.c` (read it): head parsed with
  `httparse` (head ≤ 8 KiB); `Content-Length`; chunked when `Transfer-Encoding`'s last coding is
  `chunked` (with extensions and trailers); 1xx skipped except 101 (error); 204/304 and
  `Content-Length: 0` have no body; errors for NUL in the head, conflicting Content-Length,
  Transfer-Encoding without final chunked, no framing at all, bad chunk size, bytes after chunk
  data other than CRLF, body over 128 MiB.
- Tests: every fixture response (`*.http`) parses with the right status, headers and body
  (the chunked one reassembles to `synthetic-grey-75dpi.jpg`), in every split size from 1 byte
  to whole; each error rule; deadline expiry mid-body gives a timeout error; `exchange` drains
  before writing.

## Task 3: eSCL documents, JPEG info and PDF

**Files:** `scan-core/src/{escl.rs,jpeg.rs,pdf.rs}`.

```rust
pub enum ColorMode { Grey, Colour }
pub struct ScanSettings { pub color: ColorMode, pub dpi: u16 } // dpi ∈ {75, 150, 300, 600}
pub fn scan_settings_xml(settings: &ScanSettings, caps: &Capabilities) -> String;
pub struct Capabilities { pub make_and_model: String, pub max_width: u32, pub max_height: u32,
                          pub resolutions: Vec<u16>, pub color_modes: Vec<ColorMode> }
pub fn parse_capabilities(xml: &[u8]) -> Result<Capabilities, EsclError>;
pub struct JobInfo { pub uri: String, pub state: String, pub images_completed: u32 }
pub struct ScannerStatus { pub state: ScannerState, pub jobs: Vec<JobInfo> }
pub enum ScannerState { Idle, Processing, Testing, Stopped, Down, Other(String) }
pub fn parse_status(xml: &[u8]) -> Result<ScannerStatus, EsclError>;
pub fn job_path(location: &str) -> Result<String, EsclError>; // "/eSCL/ScanJobs/1002"
pub struct JpegInfo { pub width: u32, pub height: u32, pub components: u8, pub progressive: bool }
pub fn jpeg_info(jpeg: &[u8]) -> Result<JpegInfo, JpegError>;
pub struct Page { pub jpeg: Vec<u8>, pub dpi: u16, pub info: JpegInfo }
pub fn write_pdf(pages: &[Page]) -> Result<Vec<u8>, PdfError>;
```

- `scan_settings_xml` for 75 dpi grey must equal the body of
  `tests/fixtures/m130a-scanjobs-request.http` (the request the printer accepted). Region
  2480×3508 clamped to the capabilities' maximum; settings outside the reported resolutions or
  colour modes are rejected before any XML is built (return a `Result` or validate in a
  constructor — choose one, keep it consistent).
- XML parsing matches on local names (ignore prefixes), tolerates whitespace and comments.
  Fixtures: capabilities, status idle / processing / completed. Malformed XML → error.
- `job_path`: relative path returned as is; `http://localhost[:port]/eSCL/…` → path; anything
  without `/eSCL/ScanJobs/` → error.
- `jpeg_info` walks markers to the first SOF (baseline, extended, progressive); errors for
  non-JPEG, truncated data, missing SOF, arithmetic/lossless variants. Fixtures:
  `synthetic-grey-75dpi.jpg` (620×877, 1 component), `synthetic-colour-150dpi.jpg`.
- `write_pdf`: one page per JPEG, MediaBox = pixels ÷ dpi × 72 pt, image XObject with
  `/DCTDecode`, DeviceGray/DeviceRGB/DeviceCMYK by component count (CMYK with
  `/Decode [1 0 1 0 1 0 1 0]` only if the JPEG has an Adobe APP14 marker with transform 0 —
  otherwise as is), error for zero pages. Tests read the PDF back with `lopdf` (dev-dependency):
  page count, MediaBox for 75 dpi 620×877 (595.2 × 841.92), filter, colour space, image bytes
  identical to the input JPEG.

## Task 4: The scan flow

**Files:** `scan-core/src/{lib.rs,error.rs,scanner.rs}`.

```rust
pub struct Timing { pub poll: Duration, pub request: Duration, pub idle_wait: Duration }
impl Timing { pub fn page_deadline(&self, settings: &ScanSettings) -> Duration; }
impl Default for Timing { /* poll 1 s, request 10 s, idle_wait 30 s */ }
pub struct Scanner<T: Transport> { /* transport, capabilities, timing */ }
impl<T: Transport> Scanner<T> {
    pub fn with_transport(transport: T, timing: Timing) -> Result<Self, ScanError>; // GETs caps
    pub fn capabilities(&self) -> &Capabilities;
    pub fn status(&mut self) -> Result<ScannerStatus, ScanError>;
    pub fn scan_page(&mut self, settings: &ScanSettings, cancel: &AtomicBool)
        -> Result<Page, ScanError>;
}
#[derive(Debug, thiserror::Error)]
pub enum ScanError { NotConnected, InterfaceBusy, ScannerBusy,
                     JobRejected { status: u16, detail: String }, Timeout { waiting_for: String },
                     Disconnected, Cancelled, NoPage, Protocol(String) }
```

- `scan_page` follows the design's "One scan" section exactly: wait for Idle (poll), POST,
  NextDocument polling with 503 → sleep `poll` → retry until `page_deadline`, 200 → page
  (validated with `jpeg_info`, wrapped as `Page` with the requested dpi), then `DELETE {job}`
  with its answer ignored (do not wait for 404 — see the design), cancel → `DELETE {job}` then
  `Cancelled`. A 404 before any page →
  `NoPage`. `page_deadline`: 60 s at 150 dpi grey, scaling with pixel count and colour (×3) up
  to 240 s at 600 dpi colour; tests pin the table.
- `Display` texts are the user-facing sentences from the design's error table (one sentence,
  what happened + what to do).
- Tests with `ScriptedTransport` and `Timing` set to zero/millisecond values: the observed
  sequence (Idle status, 201 relative, 503 ×4, 200 chunked) yields the synthetic page and ends
  with a DELETE of the job (whose answer, 200 or 404 or 503, never fails the scan); absolute
  Location; Processing → Idle wait; never Idle → `ScannerBusy`; POST 409/400 →
  `JobRejected` with status; 503 past the deadline → `Timeout` and a DELETE was sent; cancel
  flag set during polling → DELETE + `Cancelled`; 404 first → `NoPage`; transport
  `Disconnected` → `Disconnected`; capabilities fetch failure on construction.

## Task 5: USB transport

**Files:** `scan-core/src/usb.rs`, `scan-core/tests/hardware.rs`.

```rust
pub struct UsbTransport { /* nusb interface + bulk endpoints */ }
impl UsbTransport { pub fn open() -> Result<Self, ScanError>; }
impl Transport for UsbTransport { … }
impl Scanner<UsbTransport> { pub fn open() -> Result<Self, ScanError>; }
pub fn printer_connected() -> bool; // device present, no claim
```

- Find devices with vendor `0x03F0` that have an interface `ff/09/01` (alt 0); try those
  interfaces in order (3 then 4) until one claims; none present → `NotConnected`; all claims
  fail → `InterfaceBusy`.
- `read`: submit one bulk IN transfer of the endpoint's max packet size × N (any N; full speed is
  64, high speed 512 — the Mac runs it at high speed); a zero-length completion means "no data
  yet": wait 1 ms and resubmit; return the first non-empty data; `Timeout` at the deadline;
  `Disconnected` when the device goes away. `write`: one OUT transfer, plus a zero-length
  packet when the length is a multiple of the max packet size. `drain`: reads with a ~200 ms
  timeout until a read is empty or times out.
- Use nusb 0.2.9's current API (docs.rs/nusb/0.2.9) — it changed substantially from 0.1; do not
  guess.
- Hardware tests (`#[ignore]`, in `tests/hardware.rs`): open, capabilities match the fixture's
  model and limits, status parses, one 75 dpi grey `scan_page` yields a valid JPEG of about
  620×877 (the printer is attached to this Mac; a sheet is on the glass). Run them with
  `just app-hw-test` and report the output. **Never commit a scanned image.**

## Task 6: CLI

**Files:** `scan-cli/src/main.rs` (+ small modules if needed).

- `m130a-scan status` prints model, state and supported resolutions.
- `m130a-scan scan --out FILE.pdf [--grey] [--dpi 150|300|600]`: scans a page, prints its size
  and asks `Another page? [y/N] ` on stderr, repeats while "y", then writes the PDF and prints
  the path and page count. Ctrl-C during a scan cancels it (set the cancel flag).
  Refuses to overwrite an existing file unless `--force`.
- The page loop is a function generic over `Transport`, `BufRead` (answers) and `Write`
  (prompts) so it is tested with `ScriptedTransport` (scan-core's `testing` feature) and canned
  input: one page, two pages, error on the second page keeps... no — an error aborts without
  writing a partial PDF and says so.
- Run it once against the real printer at 150 dpi grey into the scratchpad and report the
  output; do not commit the PDF.

## Task 7: Desktop backend (Tauri)

**Files:** `app/desktop/src-tauri/{Cargo.toml,build.rs,tauri.conf.json,capabilities/*.json,
src/main.rs,src/lib.rs,src/pages.rs,src/commands.rs}`, `app/Cargo.toml` (member), icons
generated with `cargo tauri icon` from a simple placeholder SVG (keep it in the repo).

- `tauri.conf.json`: product `M130a Scan`, identifier `ro.micovi.m130a-scan`, macOS only
  bundle target `app`, `app.withGlobalTauri: true`, `build.frontendDist: "../ui/dist"`,
  `beforeBuildCommand`/`beforeDevCommand` run the UI build (`bun run build` in `../ui`),
  strict CSP allowing `page:` images. Capabilities: only the commands below and
  `dialog:allow-save`, `dialog:allow-ask`/`allow-message`.
- `pages.rs`: `PageStore` — ordered pages with ids, `add(Page) -> PageMeta`, `delete(id)`,
  `reorder(&[id])` (must be a permutation, else error), `in_order() -> Vec<&Page>`, `get(id)`,
  `dirty` flag cleared by `mark_saved()`. Unit tested.
- Commands (`commands.rs`), all returning `Result<_, String>` with the `ScanError` sentence:
  `printer_connected() -> bool`; `scan_page(color, dpi) -> PageMeta` (runs the blocking scan on
  `tauri::async_runtime::spawn_blocking`; opens the scanner per scan and drops it afterwards so
  the USB interface is free between scans; rejects a second concurrent scan);
  `cancel_scan()`; `delete_page(id)`; `reorder_pages(ids)`; `save_pdf(path) -> u32`
  (pages written, clears dirty); `has_unsaved_pages() -> bool`; `quit()`.
  `PageMeta { id, width_px, height_px, dpi, color }`.
- URI scheme `page`: `page://localhost/<id>` serves the page's JPEG with `image/jpeg`;
  unknown id → 404.
- Close guard: on window close request, if dirty, prevent close and emit `confirm-close`; the UI
  asks and calls `quit()`.
- **Done when:** `cargo tauri build --bundles app` produces `M130a Scan.app` (with a stub UI
  `dist/index.html` if Task 8 hasn't run — Task 8 replaces it), clippy/fmt/lizard clean, store
  tests pass.

## Task 8: UI (use the `impeccable` skill)

**Files:** `app/desktop/ui/{package.json,tsconfig.json,biome.json,index.html,src/*.ts,
src/styles.css,vitest.config.ts}`.

- Load and follow the `impeccable` skill for the visual design. Direction: a quiet,
  native-feeling macOS utility (system font, light and dark mode via `prefers-color-scheme`,
  generous spacing, one accent colour), not a web page. English UI text.
- One window: toolbar with **Colour/Grey** segmented control, **Resolution** (150 / 300 / 600,
  default 300), primary **Scan page** button (becomes **Cancel** while scanning, with progress
  text "Scanning… place the next page after this one finishes"), connection status
  ("Printer connected" / "Printer not connected", polled every 2 s via `printer_connected`).
  Main area: grid of page cards (`<img src="page://localhost/<id>">`, page number, delete
  button), drag-and-drop reorder plus keyboard (select, ⌘↑/⌘↓ move, Delete removes). Empty
  state explains: place a page on the glass and press Scan page. **Save PDF…** (⌘S) opens the
  native save dialog (`window.__TAURI__.dialog.save`, default `scan-YYYY-MM-DD.pdf`), then
  `save_pdf`. Errors shown inline near the toolbar, dismissible. `confirm-close` →
  `dialog.ask("You have unsaved pages. Quit anyway?")` → `quit`.
- Code: `api.ts` (typed wrappers over `window.__TAURI__.core.invoke`, minimal hand-written
  declarations — no npm runtime deps), `pages.ts` (pure page-list state: add, remove, move,
  select; unit tested with Vitest), `main.ts` (DOM wiring). Build with `bun build` into `dist/`
  (plus copying `index.html` and CSS). TypeScript strict per the user's tsconfig rules
  (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`,
  `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`,
  `isolatedModules`); `tsc --noEmit` clean; dev dependencies pinned exactly (no `^`/`~`),
  `bun install --frozen-lockfile` works.
- Extend `just app-test` with the Vitest run and `just app-lint` with `biome check`,
  `tsc --noEmit`, and lizard + line length over `app/desktop/ui/src`.
- **Done when:** the built app shows the UI, the tests and lints pass, and screenshots of the
  empty state and of a few (synthetic) pages are reviewed against the impeccable checklist.
